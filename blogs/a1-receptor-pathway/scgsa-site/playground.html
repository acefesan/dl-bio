What "paper's real cells" means

All 9,528 naive B cells from the four healthy donors in GSE164381, every gene, raw counts — the input the authors' script names ("Naive Normal B cell"). Each run draws 2 × n of them and follows the authors' own code (Thakar-Lab/scPS, "RWSD and GS simulation"), step for step: keep genes detected in at least one drawn cell; pick "signal" genes; multiply their log-normalised values by 1.2 in treatment cells; for S3/S4, append 250 genes that are zero in every control cell. The browser version rebuilds the authors' R matrix exactly on the same draws (validate/rwsd_check.js).

Two things the code says that the paper's text does not: scenario 1's "densely expressed" genes are those detected in more than 25% of cells (the text says "at least 75%"), and the "+20%" is a ×1.2 on log-normalised values. In these cells the dense genes are mostly ribosomal and mitochondrial — scenario 1 boosts housekeeping genes, not a pathway. The naive-B labels are our reconstruction (the authors' annotation isn't published); see paper-data/.

On these cells vs. the paper

Reproduced (gene set size 100, 200 cells per group): S1 detection by every method except ssGSEA; the S1 null pattern (JASMINE ~100%, AUCell ~97%, SCSE ~21%; AddModuleScore, scPS, UCell ≤ 2%); scPS losing power at 20 cells per group; the S3 trap — every method except scPS fires on sets with no condition-specific gene — and S4's much smaller effect. Not reproduced: ssGSEA almost never fires here, including in S3, where the paper says it did. SSD (Splatter fitted to the same cells, as the paper's second dataset) is sparser than the paper's — its median S1 signal gene is detected in ~15% of cells vs. their 32% — and its genes are synthetic (Gene1, …). The toy simulator (other "Data" options) is kept for comparison; it has 3,000–6,000 made-up genes and is for mechanisms, not magnitudes.

Things to try

  • Scenario 3, null sets (real cells): noise 0%, so every set is drawn from dense genes that were not changed and holds no added gene. Everything except scPS fires — and the arrows point down: the 250 extra genes in treatment cells push the set's genes down each cell's ranking. Click a treatment cell to see its added genes.
  • Then Sweep gene set size on the same setting: the "bigger is shadier" curve.
  • Scenario 1, noise 100% (real cells): sets with no boosted gene. AUCell and JASMINE flag nearly all of them, SCSE about a fifth; AddModuleScore, UCell and scPS stay quiet.
  • Scenario 4, null sets (real cells): the added genes are sparse, each treatment cell gains few detections, and the false positives almost vanish.
  • Scenario 2, 20 cells per group (real cells): scPS loses power (about a third of sets found) while AUCell, UCell and JASMINE still find them all, as the paper reports below 50 cells.
  • Scenario 2, gene set size 25, 20 cells (toy, dense): AUCell and JASMINE — the pair the paper recommends for small sparse sets — keep their power while AddModuleScore, SCSE and scPS drop.
  • Switch S3/S4 "signal" genes to ×1.2 to see the scenario as the script literally reads: the dense genes are then boosted, so scPS fires on every set (and UCell goes quiet, the boost cancelling the rank push). The paper reports scPS staying quiet in S3, so the authors' runs cannot have used the boost — the script's Signal_Level = 1.2 must have been set to 1, as in their "without signal" result folders.
