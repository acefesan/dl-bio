Playground

The paper's whole pipeline as a graph, from the source data (top) to the test. Each node does one step, holds that step's options, shows what it produced, and links to the code that does it — ours and the authors'. Change an option and everything below it reruns. Click any cell in the score node to open it.

Where this follows the authors' code, not the paper's text

Dense genes are those detected in more than 25% of cells (10% for SSD), not "at least 75%"; the "+20%" is a ×1.2 on log-normalised values; S3/S4 add 250 genes copied from a second draw of cells, and their share in a gene set is left to chance. The browser rebuilds the authors' R matrices exactly on the same random draws (validate/rwsd_check.js). On these cells the paper's results reproduce, except that ssGSEA almost never fires — including in S3 — and our SSD is sparser than theirs. Details: the four scenarios and paper-data/README.md.

Things to try

  • Scenario 3, null sets (real cells): noise 0%, so every set is drawn from dense genes that were not changed and holds no added gene. Everything except scPS fires — and the arrows point down: the 250 extra genes in treatment cells push the set's genes down each cell's ranking. Click a treatment cell to see its added genes.
  • Then Sweep gene set size (node 13) on the same setting: the "bigger is shadier" curve.
  • Scenario 1, noise 100% (real cells): sets with no boosted gene. AUCell and JASMINE flag nearly all of them, SCSE about a fifth; AddModuleScore, UCell and scPS stay quiet.
  • Scenario 4, null sets (real cells): the added genes are sparse, each treatment cell gains few detections, and the false positives almost vanish.
  • Scenario 2, 20 cells per group (real cells): scPS loses power (about a third of sets found) while AUCell, UCell and JASMINE still find them all, as the paper reports below 50 cells.
  • Scenario 2, gene set size 25, 20 cells (toy, dense): AUCell and JASMINE — the pair the paper recommends for small sparse sets — keep their power while AddModuleScore, SCSE and scPS drop.
  • In the boost node, switch S3/S4 dense genes to "boosted" to see the scenario as the script literally reads: the dense genes are then boosted, so scPS fires on every set (and UCell goes quiet, the boost cancelling the rank push). The paper reports scPS staying quiet in S3, so the authors' runs cannot have used the boost — the script's Signal_Level = 1.2 must have been set to 1, as in their "without signal" result folders.
