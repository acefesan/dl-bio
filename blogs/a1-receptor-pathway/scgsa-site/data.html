Which data is this?

Three different sources feed this site. Each page carries a badge naming its source. This page says what each one is, how they relate, and what "harmonised" does and doesn't mean.

Paper data · GEO

GSE164381, the paper's own input

Raw 10x files from GEO (Hoehn et al. 2021): 11 samples, 34,776 cells. We rebuilt the authors' subset: 9,528 naive B cells from 4 healthy donors. Also a Splatter (SSD) pool fitted to them.

Used by: Playground, every method page, The four scenarios, Scoring from zero. Not part of the Census.

Single-dataset files

Three study files from CELLxGENE

Downloaded one study at a time: HBCA neurons (~2.48 M cells), HBCA non-neuronal (~0.89 M), Tabula Sapiens (~1.14 M). Same CELLxGENE format as the Census, but each keeps its study's own extra columns — e.g. HBCA's supercluster_term with "Hippocampal CA4", which the combined Census drops.

Used by: Our A1 data and the seven-method CA4 comparison (lab 001).

Census (SOMA)

The whole CELLxGENE Census, local copy

Release 2025-11-08, stored on the home server in SOMA format. Human: 565 datasets, 96.6 M primary cells (55.8 M from 10x, healthy, in 430 datasets, roughly 8,800 donors); mouse too. A separate spatial collection holds 540 tissue sections.

Used by: What is in the Census, Cell type tree, ADORA across the Census, Gene sets and pathways (detection grids), ADORA in tissue sections (spatial collection).

How they relate: same cells, different packaging

GEO GSE164381 ─────────────► raw 10x files ──► our naive-B rebuild ──► Playground, methods (the paper's data; not in our Census work) CELLxGENE Discover: one file per study (H5AD, CELLxGENE format, + the study's own columns) ├── HBCA neurons, HBCA non-neuronal, Tabula Sapiens ──► downloaded singly ──► "Our A1 data" └── every human study (565 with primary cells), stacked ──► Census (SOMA): standard columns only, one shared gene axis ──► Census pages

So the HBCA and Tabula cells in the single-dataset files are also in the Census. A result on the Census is a broader view of overlapping data, not an independent replication of an HBCA result. The difference is packaging: the single files keep study-specific labels (CA4); the Census keeps only the standard labels, under which the hippocampal subfields are one "hippocampal pyramidal neuron" group.

What "harmonised" means — and doesn't

The Census does harmoniseThe Census does not
Metadata format: every study's cell type, tissue, disease, assay, sex, development stage is mapped to standard ontology terms.Correct batch effects. No integration across studies: a cell type that comes from one lab, one chemistry, one depth carries all of that with it.
Genes: all mapped to one reference (GENCODE), on one shared gene axis.Measure the same genes everywhere. Each study keeps its own gene list; a gene a study never measured looks like a 0 unless you check the presence table. (Our Census pages do check.)
Counts: raw counts as submitted, plus a "normalized" layer = count ÷ cell total (no ×10,000, no log).Re-annotate cells. Cell types are the submitters' own calls, translated to standard names — some broad ("neuron", "brain vascular cell"), some fine.
Duplicates: a cell re-published in several studies is flagged; is_primary_data keeps one copy.Separate cells from nuclei. Whole cells and single nuclei sit side by side (suspension_type); nearly all brain neurons are nuclei.
