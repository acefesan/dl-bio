AUCell

Rank the cell's genes from highest to lowest and ask how many of the set's genes turn up near the top. Only the top 5% of the ranking counts. Below that, nothing matters.

The question it asks

AUCell (Aibar et al. 2017, part of SCENIC) was designed to decide whether a regulon is "on" in a cell. The intuition: if a program is active, its genes should be among the cell's most highly expressed genes. So instead of averaging values, it looks at where the set's genes land in the cell's own ranking, and only near the top.

The computation

For each cell, rank all \(G\) genes by expression, highest first (\(G\) is the total number of genes, \(S\) the gene set, \(k = |S|\)). Walking down the ranking, let \(y_c(r)\) be the number of set genes seen by rank \(r\) in cell \(c\). This recovery curve climbs by one at each set gene. The score is the area under it, up to a cutoff rank \(R_{\max}\), divided by the largest area possible for a set of that size:

$$\text{AUC}_c = \frac{\int_0^{R_{\max}} y_c(r)\,dr}{\int_0^{R_{\max}} y_{\text{best}}(r)\,dr}$$

where \(r\) is a rank position (1 = the most highly expressed gene) and \(y_{\text{best}}\) is the curve you'd get if every set gene occupied the top \(k\) ranks. In the code the integral is a sum over the set genes' sorted ranks \(\rho_1 < \rho_2 < \dots < \rho_m\) that fall inside the cutoff (\(m\) is how many do; \(m \le k\)). The curve sits at height \(i\) between \(\rho_i\) and \(\rho_{i+1}\), so:

$$\text{area} = \sum_{i=1}^{m} (\rho_{i+1} - \rho_i)\cdot i, \qquad \rho_{m+1} = R_{\max}$$

The same formula with \(\rho_i = i\) (set genes at ranks \(1, \dots, k\)) gives the denominator.

On our toy cell

Ten genes is too few for a 5% cutoff, so use \(R_{\max} = 5\) for illustration. The set's ranks are B = 3, D = 4, and G is one of the tied zeros, landing somewhere in 7–10 — outside the window.

$$\text{area} = (4-3)\cdot 1 + (5-4)\cdot 2 = 3, \qquad \text{best} = (2-1)\cdot 1 + (3-2)\cdot 2 + (5-3)\cdot 3 = 9$$ $$\text{AUC} = 3 / 9 = 0.33$$

G contributes nothing. And if B had been rank 6, it would contribute nothing either: a gene just outside the window counts exactly as much as a gene at the bottom.

What the benchmarked code does

The paper passes aucell.MaxRank = NULL, and irGSEA then sets

aucell.MaxRank = ceiling(0.05 * nrow(aucell.rank))   # top 5% of genes

Rankings come from AUCell_buildRankings, which ranks with ties.method = "random". Every tied zero gets a random rank, re-drawn per cell. AUCell's own scoring function, verbatim:

x <- sort(x[x < aucThreshold])
y <- seq_along(x)
sum(diff(c(x, aucThreshold)) * y) / maxAUC

Zero policy, and what leaks in

Zeros: tied, then shuffled at random. With 20,000–60,000 genes and a window of 5%, the window usually holds only expressed genes — unless the cell detects fewer genes than the window is wide. Then some randomly shuffled zeros fall inside it, and set genes that are zero enter the window by chance.

From outside the set: every gene's rank. A set gene can drop out of the window because other genes rose, with its own expression unchanged. And the score is magnitude-blind: a 1% change that pushes a gene across the cutoff counts fully, while a tenfold change below the cutoff counts not at all.

On our A1 data

AUCell ranked Hippocampal CA4 1st of 21 on the 8-gene panel and 9th on the 61-gene panel. One concrete mechanical point: HBCA has 58,232 genes, so the 5% window is 2,912 ranks wide. The median Upper rhombic lip cell detects only 1,987 genes, so its window necessarily spills into about 900 randomly shuffled zeros; the median CA4 cell detects 7,604. The same score therefore measures different things in different cell types.
