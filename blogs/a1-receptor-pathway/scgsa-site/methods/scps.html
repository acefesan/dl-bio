Covariance · within the set

scPS

The paper's own method. Run PCA on the gene set's genes alone, keep the components that explain half their variance, combine each cell's position on them, and multiply by the set's mean expression. It is the only method that never looks outside the set — which is both why it survived scenario 3 and why it is fragile.

The question it asks

A pathway isn't just "genes that are high". Its genes should go up and down together across cells. If a set is coherently active, the cells will spread out along a common axis of co-variation, and PCA finds that axis. scPS scores a cell by how far along the set's main axes of co-variation it sits, then scales by how much the set is expressed at all.

scPS adapts the authors' earlier single-person transcription-factor score (spTFscore, Cornwell et al. 2021).

The computation, as the paper writes it

The paper's Equation 1:

$$\text{scPS}_c = \mu_c \times \sum_{i=1}^{m} (s_{ic} - s_{\min}) \times v_i$$
  • \(\mu_c\): the mean expression of the set's genes in cell \(c\).
  • \(s_{ic}\): cell \(c\)'s score on principal component \(i\), from PCA on the set's genes only.
  • \(s_{\min}\): "the minimum of the \(s_i\) among all the cells", which shifts scores to be non-negative.
  • \(v_i\): "the percentage of variance explained by the PC".
  • \(m\): the number of PCs needed to reach 50% cumulative variance.

The computation, as the code does it

  1. ScaleData: centre and scale each set gene across all cells (z-scores, clipped at 10).
  2. RunPCA(features = set, npcs = 10, weight.by.var = FALSE). Cell embeddings are the unit-length left singular vectors.
  3. \(v_i = \sigma_i^2 / \sum_j \sigma_j^2\) over the PCs Seurat stored; \(m\) = the first PC where the cumulative sum exceeds 0.5.
  4. Shift the whole embedding matrix by its single smallest value.
  5. Per cell: the square root of the \(v\)-weighted sum of shifted scores over the first \(m\) PCs, times the mean of the set's log-normalised expression.
$$\text{scPS}_c = \mu_c \times \sqrt{\sum_{i=1}^{m} \big(s_{ic} - \min_{j,c'} s_{jc'}\big)\, v_i}$$
Three differences between the paper and its code
  1. A square root. Equation 1 has none; scPS_2024.R and scPS_2025.R both take sqrt(rowSums(...)). Rankings are unchanged by a monotone transform of the PC part, but the product with \(\mu_c\) is not.
  2. One minimum, not one per component. The paper subtracts the minimum of each \(s_i\); the code subtracts the minimum of the entire embedding matrix (embeddings - min(embeddings)).
  3. What "variance explained" is divided by. With Seurat's default approx = TRUE, only the 10 computed standard deviations are stored, so \(v_i\) is a share of the top-10 variance. With approx = FALSE, Seurat stores all of them and \(v_i\) becomes a share of total variance. On a 30-gene test set this moved \(m\) from 5 PCs to 9. The authors left # approx = FALSE commented out on that line, so the published behaviour is the top-10 version.
A bug in the 2024 code, fixed in 2025

When a single PC already explains more than half the variance (\(m = 1\)), scPS_2024.R runs

sqrt(sum(currWeightedPC[ , 1:(maxCombPC[currGS])]))

— summing over all cells and assigning that one number to every cell. The PC component becomes a constant, and scPS collapses to plain mean expression times a constant. scPS_2025.R changes the line to sqrt(currWeightedPC[ , 1:(maxCombPC[currGS])]), per cell. Verified by running both code paths on a toy matrix. The paper was published with the 2024 version.

A worked example, computed live

Six cells and our three set genes (log-normalised values). Cells 1–3 are control, 4–6 treatment. PCA can't be done on one cell, so this example has several.

A principal component's sign is mathematically arbitrary: \(v\) and \(-v\) describe the same axis. But the shift-by-minimum step makes scPS depend on it. Press the first button and watch the ranking reorder completely.

Here PC1 alone explains more than half the variance, so \(m = 1\) — exactly the case the 2024 code mishandles. Press the second button: the PC column becomes identical for every cell, and scPS turns into mean expression times a constant.

This is not a toy concern

Scoring the same simulated matrix with the real R pipeline and with this site's JavaScript — identical data, identical steps — the two scPS vectors correlated at r = −0.39. After aligning each PC's sign, r = 0.994. On HBCA, re-running scPS with a different random seed changed which cell type ranked first, because irlba's random start changes the signs it returns.

Other practical limits

  • npcs = 10 is hard-coded. A gene set needs at least 11 genes, or RunPCA cannot return 10 components. Our 8-gene A1 panel had to be run with npcs = 7.
  • The authors' own example filters KEGG to pathways of 50–60 genes (predBind_maxMin <- list(max = 60, min = 50)).
  • Few cells: "with sparse data below 50 cells, where PCA cannot provide accurate covariance estimates, scPS is not the best method."

Zero policy, and what leaks in

Zeros: ordinary values after scaling. A gene that is zero in most cells becomes a near-constant column with a few outliers, contributing little shared variance.

From outside the set: nothing. The scaling, the PCA and the mean all use only the set's genes. This is the whole reason it survives scenario 3. Extra genes elsewhere in the cell cannot touch any of its inputs.

On our A1 data

scPS ranked Hippocampal CA4 1st on the 8-gene panel (5th on the 61-gene panel), but that needed npcs = 7, and one of three random seeds put Amygdala excitatory first instead. An earlier note in this project recommended re-running with approx = FALSE for stability. As shown above, that also changes what "50% of the variance" means, so it is a different method, not a more stable run of the same one. The faithful stable version is exact SVD with \(v_i\) normalised over the first 10 PCs. Because it is the one method immune to the genes-detected-per-cell confound, a sign-stable scPS is the most useful check on the CA4 result. Details.
